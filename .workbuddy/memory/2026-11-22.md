## 三处根因 + 修复
1. **清单缺 source 字段**：官方 manifest 都有 `source: builtin/steam/external`，AppInfoManager 跳过无 source 的清单 → `manifest_json` 加 `"source": "external"`
2. **路径/工作目录失效**：exe 与 working_directory 改绝对路径（`canonicalize()` + current_dir fallback），不写死盘符
3. **注册的 SteamVR 不对**：新增 `register_with_steamvr(runtime_root, game)`，用该 SteamVR 自己的 `bin/win64/vrcmd.exe --appmanifest` 实时注册；openvrpaths 仍写（重启兜底）。UI `register_game()` 串起来：先 ensure openvrpaths（runtime[0] 指向所选 SteamVR）→ 写清单 → vrcmd 实时注册；SteamVR 没跑时跳过实时注册返回成功（重启生效），不误报失败
4. **离线启动失败**：`launch()` 固定 sleep 4s 改为轮询 vrserver（60s 超时、500ms 间隔、起来后再 grace 2s），起来后重试实时注册
5. openvrpaths `ensure_openvr_paths_file` 保证 `apps` 数组始终存在（Steam 会重写该文件丢掉 apps）

## 投屏页弹窗风暴根因（07:35）
- 现象：用户一进入"有线投屏"页就不停弹窗。排查：HwVRDesktop.exe 未运行、二进制无 MessageBox 字符串、setup wizard/new version popup 都关 → 不是渲染器/dashboard 弹窗
- **真根因**：wired_display.rs 的 ui() 每帧调用 renderer_running()（两次），内部 `Command::new("tasklist").output()`。GUI 程序启动 console 子进程会闪黑色控制台窗口，60fps 下就是"弹窗风暴"
- 修复：加 `CREATE_NO_WINDOW`(0x08000000) 到 tasklist/taskkill/渲染器 spawn（std::os::windows::process::CommandExt）；进程状态改为缓存字段 + 每秒轮询一次（PROCESS_POLL_INTERVAL），UI 只读缓存不再每帧 spawn
- 验证：test 12 全过；release 32,714,752 B 部署 artifacts。用户需**关闭并重开 dashboard** 才生效（旧进程还在内存里）
- 教训：egui UI 绘制路径里绝不能 spawn console 进程；GUI 程序所有子进程都要 CREATE_NO_WINDOW
